# Отчёт: доказательный RAG по ТФКП

Статус: реализован код, проверен локальный BM25 и контракты. Генеративные результаты не измерены. Официальные corpus/runtime/dev JSONL отсутствовали; по уточнению пользователя данные созданы из приложенных PDF и QA. Это собственный пилот, а не подтверждённый прогон официальной конфигурации.

## Данные и формулы

`prepare_data.py` извлекает все 147 страниц через PyMuPDF 1.26.6 и fonttools 4.61.1, восстанавливает кириллическую кодировку шрифта и создаёт один исходный блок на страницу. ID содержит первые 12 символов SHA-256 PDF и номер страницы с 1. PDF SHA-256 начинается с `629f4b668ff4`. Исходники не редактируются вручную. Все операции повторяемы кодом; LLM при подготовке/индексации не используется.

15 вопросов, варианты, категории и эталоны извлечены из предоставленного QA. Один допустимый набор источников — все указанные в QA страницы. Для отказов списки пусты, сохранено недостающее сведение. Такие страничные gold грубее официальных блоков и не гарантируют минимальности ссылок. Добавлены 8 авторских вопросов: условия устранимости/Пикара; нули и полюсы/особенность на бесконечности; два вычисления вычетов; два случая недостаточности данных.

В исходном извлечении Poppler терялись черты сопряжения (с. 12, 20), замыкание круга и модуль отношения (с. 36), структура дробей, степеней и знаки интегралов/сумм. Исправленный `rag/pdf_math.py` использует имена глифов встроенных TeX-шрифтов, их реальные контуры, координаты базовых линий и графические черты PDF. Восстанавливаются TeX-представления дробей, надчёркиваний, вложенных индексов, корней, модулей и кусочных выражений. Проверяется сохранение исходных математических глифов при группировке. Нет таблицы формул по страницам/ID вопросов и обращения к QA из извлекателя.

Ключевые формулы всех 11 аудированных страниц проверены регрессиями на исходном PDF; все 147 страниц извлекаются повторяемо без неизвестных глифов и управляющих символов. 13 страниц с неразобранными линиями/рисунками помечены для ручного контроля в `data_manifest.json`. Это геометрическая транскрипция, а не доказательство сохранности каждой формулы произвольного PDF. Официальный качественный корпус предпочтителен при его наличии.

## Чанкинг, поиск, контекст

Окна до 1000 символов, перекрытие до 160; граница по строке. Dense-окна дополнительно ограничиваются реальным E5-tokenizer до 512 токенов. Сохраняются неизменные фрагменты текста и диапазоны в исходном блоке. Индекс проверяется по хешам, каждый загруженный фрагмент сверяется с исходной строкой блока.

BM25 использует `k1=1.5, b=0.75`, Unicode-нормализацию и русский Snowball только в поисковом представлении. Dense: `intfloat/multilingual-e5-small`, нормализованные векторы, CPU FAISS IndexFlatIP. Фактическое число параметров проверяется ≤1 млрд; точный commit и хеши артефактов фиксируются подготовкой моделей. В текущей среде SHA ещё не разрешены: Hugging Face отклонён прокси с 403. Ревизии не выдуманы.

Слияние: RRF(d)=Σ 1/(60+rank(d)). До 32 кандидатов, разнообразие страниц, до 8 фрагментов; финальный режим добавляет соседние окна той же секции. Длинный запрос dense делится на части. В поиск поступает вопрос и тексты вариантов; gold, категория и ID вопроса не используются. Предсказания между вопросами не переносятся.

Контекст ограничивается tokenizer/chat template именно разрешённой Qwen. В системном сообщении требуются проверка всех вариантов, короткий вывод, минимальные ссылки и отказ при недостаточности. Успешный ответ требует непустых answer_ids/citations; отказ — пустых списков и причины. Pydantic контролирует структуру, но не доказывает математическую верность обоснования.

## Генерация и стоимость

Все генеративные шаги предусмотрены только через Qwen3.5-4B API. Один вызов; в финальных режимах максимум одна дополнительная попытка после некорректного JSON/ID/ссылок. Логируется решение, определившее повтор. Поисковых адаптивных циклов нет.

Расход — только серверный usage. Thinking включён в completion_tokens без повторного прибавления. C_i=input_i+4 output_i+256 calls_i. Перед запросом проверяются суммарные лимиты 4/16384/4096 и окно 8192 с резервом неизменного max_tokens и запасом входа. Нет скрытых retries и изменения sampling. Сетевой сбой/непроверяемый usage маркируется технической ошибкой, получает нулевую оценку и не маскируется содержательным отказом.

Runtime создан пользователем через эту реализацию (`official=false`): temperature=0, top_p=1, max_tokens=1024, thinking=false, CPU=2, RAM=4096 MiB, timeout=120 s. Это не восстановленные ограничения организатора. Не заданы endpoint, ключ, фактическая ревизия/квантизация сервера. Пока они не проверены, генерация блокируется. После получения официального runtime параметры следует привести к нему до всех экспериментов.

## Эксперименты

| Конфигурация | Изменение | Accuracy / Q / стоимость |
| --- | --- | --- |
| no_context | Без источников | Не измерены; Q не применяется |
| simple | BM25, один поиск, один вызов | Не измерены |
| final | BM25+E5+RRF, соседи, проверка | Не измерены |
| no_dense | Финальная без dense | Не измерены |
| no_neighbors | Финальная без соседей | Не измерены |

Выводы абляций пока невозможны. `experiments.csv` содержит названия режимов и пустые метрики. `dev_answers.jsonl` и `dev_trace.jsonl` появятся только после реального успешного прогона. Mock API в тестах проверяет контракты и не является экспериментом. Официального baseline/C_ref нет; локальный simple baseline будет отдельной явно названной точкой сравнения.

Реально измерена диагностика BM25 без генерации: средняя доля эталонных страниц в первых восьми разнообразных кандидатах — 0.694444 по 12 разрешимым dev-вопросам как до, так и после исправления извлечения; полностью покрыты 7 из 12. Это recall поиска до токенного упаковщика, **не accuracy, Q или качество финального RAG**. В исходной версии: 147 блоков, 593 окна, 10.473 s, пиковый RSS 55.574 MiB, индекс без манифеста 2 940 906 байт. После исправления: 147 блоков, 463 окна, сборка 2.231 s, RSS 51.797 MiB. Оборудование: Linux x86_64, 3 доступных CPU, Python 3.11.11. Измерений ресурсов dense нет. Исправление смысловых потерь само по себе не повысило эту метрику поиска; нужны отдельные поисковые эксперименты.

## Три наблюдаемые ошибки поиска исходной версии

1. «Голоморфность интеграла Коши» (QA №6). Первые страницы: 81, 31, 46, 42, 26, 56, 41, 66. В QA нужны 31 и 33; с. 33 пропущена. Совпадение общих слов про кривые и непрерывность вытесняет формулу производных. Добавление dense/соседей — гипотеза улучшения, пока не подтверждённая прогоном.
2. «Факториал в интегральной формуле» (QA №7). Найдены 40, 94, 105, 60, 73, 145, 137, 117; нужные 20 и 34 не вошли. Вопрос преимущественно символьный, формулы PDF и LaTeX представлены по-разному; BM25 ищет слова про окружность вместо основания вычисления.
3. «Бесконечно много нулей» (QA №12). Найдены 76, 66, 42, 114, 51, 14, 83, 10; требуются 21, 37, 38. Слова «нули» и обозначения f/g/n не отделяют теорему единственности от других теорем. Нужна проверка семантического поиска на новых вопросах, не обработчик по ID.

Это реальные ошибки retrieval-диагностики; ошибки ответов Qwen не наблюдались из-за отсутствия запуска.

## Проверка и ограничения сдачи

Тесты проверяют схемы, ссылочную целостность, сохранение символов, лимиты всех попыток/thinking, HTTP-заголовки, неверные citations, сетевые сбои, реальный FAISS на известных векторах, независимость ID и пересборку с другими путями. Добавлены регрессии геометрии формул, шрифтовых глифов, сопряжения в знаменателе, вложенных индексов, растянутых модулей и полный повторный аудит частного PDF. Результаты исправленного извлечения сохранены в `extraction_validation.json`; `local_validation.json` относится к исходному прогону.

Зависимости полностью закреплены; реальный импорт CPU-библиотек проверен. Полный dense/Qwen-пайплайн не выполнен. Нужны разрешённые веса, сервер, официальный runtime при его наличии, пять прогонов и ручная проверка обоснований. Публикуются исходники, тесты, документация, авторские вопросы и небольшие результаты локальной проверки. Корпус/PDF/индексы/веса/секреты исключены из публичной версии.

Внешний код: PyMuPDF, fonttools, Snowball, Sentence Transformers, Transformers, PyTorch CPU, FAISS, Pydantic, HTTPX, pytest; в первоначальном извлечении использовался Poppler. Реализация, тесты и авторские вопросы созданы с помощью OpenAI Codex; сторонних ответов и генеративных моделей для решения корпуса не использовалось.
